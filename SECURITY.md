# RelayIt Security Guide

## Deployment requirements

- Run behind HTTPS and an authenticated reverse proxy for any shared or
  production deployment.
- Keep Streamlit bound to `127.0.0.1`; do not expose its websocket directly to
  the internet.
- Configure strong, unique user passwords through `RELAYIT_AUTH_USERS_JSON`.
- Store `.env` and the SQLite database outside source control with restrictive
  filesystem permissions.
- Use a managed encrypted database, tenant isolation, backups, retention, and
  deletion controls before processing real customer data.
- Pin dependencies from `requirements.txt` and run `pip-audit` in CI.

## Authentication and authorization

RelayIt requires an authenticated configured user. Passwords are stored as
PBKDF2-SHA256 hashes generated by `python -m relayit.auth`; plaintext passwords
must never be committed.

Roles:

- `analyst`: view ticket data and run support workflows.
- `reviewer`: analyst permissions plus human escalation replies.
- `admin`: reviewer permissions and deployment/user administration when added.

The UI and repository authorization checks must both remain enabled. Do not
trust hidden navigation controls as authorization.

## Secrets

Keep API keys, password hashes, session secrets, and production database paths
in a secret manager or protected environment. Never print them in logs or
include them in screenshots, tickets, prompts, or audit exports.

## AI and customer data

The deterministic mode is the safe default. Before enabling a hosted model:

- Treat ticket text and retrieved documents as untrusted prompt content.
- Use an explicit allowlist for tools and validate every model output.
- Do not send credentials, full audit traces, or unnecessary PII to providers.
- Set request size, time, and iteration limits.
- Require human approval for external side effects and customer replies.

## Vulnerability reporting

Do not disclose vulnerabilities publicly before maintainers have had an
opportunity to fix them. Report privately to the repository maintainer with
steps to reproduce, affected commit/file, impact, and a suggested mitigation.
Never include live credentials or customer data in a report.
